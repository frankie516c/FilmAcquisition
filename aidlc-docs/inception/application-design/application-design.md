## 3. 핵심 설계 문제 5가지의 해결 방식

### 문제 1 — 역할별 응답 필드 제거 (FR-022)

**해결**: `X1 AuthorizationPolicy`가 `{엔티티.필드 → 조회 가능 역할}` 정책을 선언하고, `X2 SerializationGate`가 모든 응답에서 해당 키를 **제거**한다. 값을 `null`로 바꾸지 않는다.

**핵심 안전장치**: 정책에 등록되지 않은 필드의 기본값은 **차단**이다. 새 필드를 추가하고 정책 등록을 잊으면 "보여야 할 게 안 보이는" 버그로 나타나지 실수로 노출되지 않는다. 실패 방향이 안전한 쪽이다.

**두 층위 분리**
- 동작 권한(누가 무엇을 할 수 있나) → 서비스 진입 시 `requireRole` → 403
- 필드 권한(누가 무엇을 볼 수 있나) → API 경계의 직렬화 시 키 제거 → 오류 아님

---

### 문제 2 — 재무 계산식 단일 정의 (NFR-008)

**해결**: 산식은 `D1 FinancialCalculator` **한 모듈에만** 존재한다. 화면(C5), 대시보드(C6), 내보내기·리포트(C7)가 모두 이 모듈을 호출한다.

**검증 방법**: 코드에서 ROI·손익분기 계산식이 `D1` 밖에 존재하면 설계 위반이다(component-dependency.md 6절 위반 #4). PBT 속성 P1~P5가 `D1`에만 적용되므로 사본이 생기면 테스트가 그것을 검증하지 못한다.

---

### 문제 3 — 이력 append-only (FR-006)

**해결**: `StageTransitionRepository`에 `update`·`delete` 메서드를 **정의하지 않는다.** 서비스가 실수로 호출할 수단 자체가 존재하지 않으므로 타입 시스템이 컴파일 단계에서 막는다.

**보조 장치**: 단계 변경과 이력 기록을 하나의 트랜잭션(T1)으로 묶어 "단계는 바뀌었는데 이력이 없는" 상태를 방지한다. 이것이 US-008의 PBT 속성 P2(체류 일수 총합 = 경과 일수)가 성립하는 전제다.

---

### 문제 4 — 네 출력 경로의 동일 마스킹 (FR-018, FR-020)

**해결**: HTTP JSON · CSV · Excel · PDF 네 경로가 모두 `X2` 게이트를 통과한 뒤에 형식 변환된다.

**순서 규칙**: `X2.serializeForExport` → `D4.serializeToCsv` 순서를 지킨다. 뒤바뀌면 마스킹 대상 값이 파일 문자열에 이미 포함된 뒤 제거를 시도하게 된다. 제거된 필드는 **컬럼 목록에서도 빠지므로** CSV 헤더에 빈 열이 남지 않는다.

---

### 문제 5 — 순수 함수의 프레임워크 비의존 (NFR-007)

**해결**: `D1`~`D6`은 **아무것도 import 하지 않는다.** 현재 시각조차 `ctx.now`로 주입받는다.

**PBT 대상 4개와 검증 속성**

| 모듈 | 검증 속성 (요약) |
|---|---|
| `D1` 재무 계산 | 손익분기 = 총 인수비용 · 매출 증가 시 ROI 단조 비감소 · 0 나누기 시 `null` · 결과 정수 보존 |
| `D2` 체류 일수 | 모든 일수 ≥ 0 · 총합 = 등록 후 경과 일수 · 구간 비중첩 |
| `D3` D-day | 동일 날짜면 D-0 · 하루당 정확히 1 증가 · Asia/Seoul 달력일 기준 |
| `D4` CSV | 왕복 무손실 (한글·쉼표·따옴표·줄바꿈 포함) · 파싱 오류 시 예외 없이 오류 목록 반환 |

## 4. 트랜잭션 경계 요약

| # | 대상 | 묶는 이유 |
|---|---|---|
| T1 | 단계 변경 + 이력 append | 이력 누락 시 체류 일수 속성이 깨짐 |
| T2 | 작품 삭제 + 하위 전체 | 고아 레코드 방지 |
| T3 | 작품 생성 + 최초 이력 append | 체류 일수 계산의 기준점 확보 |
| T4 | 코멘트 생성 + 멘션 알림 | 코멘트만 남고 알림이 없는 상태 방지 |
| T5 | CSV 반영 (선택 행 집합) | 부분 반영 중간 상태 방지 |
| T6 | Executive 수 조회 + 역할 변경·삭제 | 마지막 관리자 보호의 경쟁 상태 방지 |
| T7 | 알림 중복 확인 + 생성 | 중복 알림 방지 |

이 문서는 **컴포넌트 경계와 시그니처**까지만 정의한다. 다음은 Functional Design(유닛별)에서 정의한다.
