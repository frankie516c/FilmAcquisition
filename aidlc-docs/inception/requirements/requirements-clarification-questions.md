## 🔴 모순 1: 딜·금액 정보가 관리 대상에서 빠졌는데, 여러 기능이 금액 데이터를 요구함

그런데 다른 답변들은 금액 데이터가 있어야만 동작합니다:

## 🔴 모순 2: 개인 학습용 로컬 PoC인데 인증·권한 요구는 프로덕션급

**Q1(E) 개인 프로젝트 / 학습·포트폴리오** + **Q15(A) 로컬 프로토타입** + **Q18(B) 보안 규칙 생략**을 선택하셨습니다.

그런데 **Q16(A)**에서는 **로그인 + 역할 기반 권한(RBAC) + 역할별 금액·기능 제한**을 요구하셨습니다.

- RBAC과 금액 마스킹은 그 자체가 보안 기능인데, 이를 검증할 SECURITY 확장 규칙은 끄셨습니다
- 개인 PoC 기준으로는 인증 구현이 전체 작업량의 상당 부분을 차지하며, 정작 대시보드의 핵심 가치(파이프라인·지표·평가)와는 무관합니다

### Clarification Question 2
인증·권한을 어느 수준으로 구현할까요?

A) **PoC용 간이 RBAC** — 실제 인증 서버 없이 로컬 계정(이메일+비밀번호 해시)으로 로그인하고, 3개 역할(Scout / Analyst / Executive)에 따라 화면·금액 노출을 제어. 포트폴리오에서 "권한 설계를 했다"를 보여주기에 충분 (**권장**)

B) **역할 전환만** — 로그인 없이 상단에서 역할을 선택(전환)하면 그 역할 기준으로 화면이 바뀜. 권한 개념은 시연하되 인증 구현은 생략 (가장 빠름)

C) **본격 인증 구현** — 세션/JWT 기반 로그인, 비밀번호 정책, 감사 로그 포함. 이 경우 **Q18(보안 확장)을 A(적용)로 변경하는 것을 권장**합니다
