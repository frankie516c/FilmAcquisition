## 2. 비즈니스 컨텍스트

### 2.1 문제 정의
영화 판권 인수(acquisition) 업무는 검토 대상 작품이 스프레드시트와 이메일에 흩어져 있어 다음 문제가 복합적으로 발생한다 (Q2 = E):

- **가시성 부재** — 검토 중인 작품이 어느 단계에 얼마나 쌓여 있는지 파악 불가
- **주관적 의사결정** — 작품별 수익성 판단 근거가 정량화되어 있지 않음
- **만료 리스크** — 오퍼 유효기간·계약 기간이 추적되지 않아 놓치는 건이 발생
- **협업 단절** — 작품에 대한 평가와 의견이 개인 문서에 흩어져 축적되지 않음

### 2.2 제품 목표
인수 파이프라인의 **현황·평가·수익성·마감**을 하나의 화면에서 관리하는 웹 대시보드를 구축한다. 작품 발굴부터 계약 체결까지의 흐름을 단일 시스템에서 추적하고, 평가와 재무 판단 근거를 작품에 귀속시켜 축적한다.

### 2.3 프로젝트 성격 (중요 전제)
본 프로젝트는 **개인 학습·포트폴리오 목적의 로컬 실행 프로토타입**이다 (Q1 = E, Q15 = A). 따라서:

- 실제 조직의 운영 데이터나 규정을 반영하지 않으며, 도메인 모델은 업계 일반 관행에 기반한 합리적 근사치다
- 프로덕션 배포, 고가용성, 실 사용자 데이터 보호를 목표로 하지 않는다
- **이 시스템을 실제 인수 업무에 사용하려면** 보안 확장(SECURITY)과 복원력 확장(Resiliency)을 활성화한 재설계, 그리고 법무 검토를 거친 계약·판권 모델 재정의가 선행되어야 한다

## 3. 사용자 페르소나 및 권한 (RBAC)

### 3.1 페르소나 (Q3 = B, C, E)

| 역할 | 페르소나 | 주요 목표 |
|---|---|---|
| **Scout** | Acquisition Manager / Scout | 작품을 발굴하고 스크리닝·평가를 입력하며 파이프라인 단계를 갱신한다 |
| **Analyst** | 재무·비즈니스 분석가 | 딜 조건을 기록하고 인수비용 대비 수익성을 계산해 판단 근거를 제공한다 |
| **Executive** | 경영진 / C-Level | 포트폴리오 현황과 마감 임박 항목을 열람하고 리포트를 내보낸다 |

**제외된 페르소나**: Acquisition Executive(최종 승인권자), 법무·계약 담당자 — 이번 범위에서 제외 (Q3)

### 3.2 권한 매트릭스 (CQ2 = A: PoC용 간이 RBAC)

범례: `CRUD` 전체 편집 · `R` 조회 전용 · `—` 접근 불가(마스킹 처리) · `Y/N` 실행 가능 여부

| 기능 | Scout | Analyst | Executive |
|---|---|---|---|
| 작품 등록·수정·삭제 | CRUD | R | R |
| 영화제·수상 이력 | CRUD | R | R |
| 평가 스코어카드 | CRUD | R | R |
| 코멘트 작성 | CRUD | CRUD | CRUD |
| 파이프라인 단계 변경 | Y | Y | N |
| 딜 — 오퍼 금액·유효기간 | R | CRUD | R |
| 딜 — MG·러닝 로열티·계약 조건 | — | CRUD | R |
| 재무 분석 (ROI·손익분기) | — | CRUD | R |
| 판권 (영토·계약 기간) | R | CRUD | R |
| CSV 가져오기·내보내기 | Y | Y | N |
| PDF·Excel 리포트 생성 | N | Y | Y |
| 사용자 계정 관리 | N | N | Y |

**금액 마스킹 규칙 (Q16 = A)**: Scout 역할에게는 MG·러닝 로열티·계약 조건·재무 분석 결과가 화면에서 `***`로 마스킹되며, 해당 필드는 **API 응답 자체에서 제거**된다(클라이언트 측 숨김이 아님). 오퍼 금액은 파이프라인 운영에 필요하므로 Scout도 조회 가능하다.

> **가정 A-1**: 위 마스킹 경계는 "평가자(Scout)와 재무 판단(Analyst)의 분리"라는 일반 관행에 근거한 설계 판단이다. 다른 경계를 원하시면 조정 가능하다.

## 5. 기능 요구사항 (Functional Requirements)

### 5.1 작품 관리

**FR-001 — 작품 등록 및 관리**
Scout는 작품을 등록·수정·삭제할 수 있다.
관리 항목: 제목, 원제, 감독, 출연(다중), 장르(다중), 러닝타임, 제작국가, 제작언어, 제작연도, 등급, 시놉시스, 담당자.
- *수용 기준*: 제목·제작연도는 필수. 동일 원제 + 제작연도 조합이 이미 존재하면 등록 시 중복 경고를 표시한다.

**FR-002 — 영화제·수상 이력 관리**
작품별로 영화제 출품·초청 이력과 수상 내역을 다건 등록할 수 있다.
관리 항목: 영화제명, 연도, 부문(경쟁/비경쟁), 초청·수상 구분, 수상명, 평단 반응 메모.
- *수용 기준*: 한 작품에 이력 0건 이상 등록 가능하며, 작품 상세에서 연도 내림차순으로 표시된다.

**FR-003 — 작품 검색 및 필터**
작품 목록에서 제목 부분 일치 검색과 다중 조건 필터(파이프라인 단계, 장르, 제작국가, 제작연도 범위, 담당자)를 적용할 수 있다.
- *수용 기준*: 필터 조건은 URL 쿼리에 반영되어 새로고침·공유 시 유지된다.

### 5.2 인수 파이프라인

**FR-004 — 표준 파이프라인 단계 (Q4 = A)**
모든 작품은 다음 7개 단계 중 하나에 위치한다:

```
발굴(Discovery) -> 스크리닝(Screening) -> 평가(Evaluation) -> 오퍼(Offer)
    -> 협상(Negotiation) -> 계약체결(Closed Won)
                         -> 반려(Rejected)
```

- `계약체결`과 `반려`는 종료 상태이며, 종료 상태에서 이전 단계로 되돌리는 것도 허용한다(오기입 정정 목적).
- *수용 기준*: 단계는 시스템 고정값이며 사용자가 추가·삭제할 수 없다.

**FR-005 — 단계 전환 (CQ3 = A)**
Scout와 Analyst는 승인 절차 없이 작품의 단계를 임의 단계로 변경할 수 있다. Executive는 변경할 수 없다.
- *수용 기준*: 단계 변경 시 이전 단계, 이후 단계, 변경자, 변경 시각, 사유 메모(선택)가 이력으로 기록된다.

**FR-006 — 단계 변경 이력 조회**
작품 상세에서 단계 변경 이력을 시간순으로 조회할 수 있으며, 각 단계에 머문 기간(일수)이 함께 표시된다.
- *수용 기준*: 이력은 수정·삭제 불가(append-only)다.

**FR-007 — 칸반 보드 뷰**
파이프라인 단계를 열로 하는 칸반 보드에서 작품 카드를 드래그하여 단계를 변경할 수 있다.
- *수용 기준*: 드래그 완료 시 FR-005의 이력이 동일하게 기록된다. Executive에게는 드래그가 비활성화된다.

### 5.3 평가 및 협업

**FR-008 — 평가 스코어카드 (Q5 = D)**
Scout는 작품별 평가를 등록한다.
관리 항목: 평가 항목별 점수(작품성, 상업성, 화제성, 타깃 적합성 — 각 1~5점), 총평, 시사 기록(시사일, 장소, 참석자), 타깃 관객층.
- *수용 기준*: 항목별 점수의 평균이 종합 점수로 자동 계산되어 작품 목록·카드에 표시된다. 한 작품에 평가자별로 복수 평가를 등록할 수 있다.

**FR-009 — 코멘트 (Q9 = B)**
모든 역할은 작품별 코멘트를 작성·수정·삭제(본인 것만)할 수 있다.
- *수용 기준*: 코멘트는 작성자·작성시각과 함께 최신순으로 표시된다.

**FR-010 — 멘션 알림**
코멘트에서 `@사용자명` 형태로 다른 사용자를 멘션하면 해당 사용자의 앱 내 알림 센터에 알림이 생성된다.
- *수용 기준*: 멘션된 사용자만 알림을 받으며, 알림 클릭 시 해당 코멘트 위치로 이동한다.

### 5.4 딜 및 판권 (CQ1 = A)

**FR-011 — 딜 정보 관리**
Analyst는 작품별 딜 정보를 등록·수정한다.
관리 항목: 요청가(asking price), 오퍼 금액, 오퍼 제출일, **오퍼 유효기간(만료일)**, MG(최소보증금), 러닝 로열티율(%), 계약 조건 메모.
- *수용 기준*: 모든 금액은 KRW 정수로 저장되며, 화면에는 천 단위 구분 기호와 함께 표시된다. Scout에게는 MG·러닝 로열티·계약 조건이 마스킹된다.

**FR-012 — 기본 판권 관리 (Q6 = B)**
Analyst는 계약된 작품의 판권 정보를 등록한다.
관리 항목: 영토(다중 선택, 국가/권역), 계약 시작일, 계약 종료일.
- *수용 기준*: 종료일은 시작일보다 이후여야 한다. **영토 간 권리 충돌 검증은 수행하지 않는다**(Out of Scope).

**FR-013 — 단일 시나리오 재무 계산 (Q7 = B)**
Analyst는 작품별 재무 입력값을 등록하고, 시스템은 다음을 자동 계산한다:

| 계산 항목 | 산식 |
|---|---|
| 총 인수비용 | 오퍼 금액(또는 MG) + P&A(마케팅) 예산 + 기타 비용 |
| 예상 손익 | 예상 매출 − 총 인수비용 |
| ROI (%) | (예상 매출 − 총 인수비용) ÷ 총 인수비용 × 100 |
| 손익분기 매출 | 총 인수비용 |

- *수용 기준*: 총 인수비용이 0인 경우 ROI는 계산하지 않고 `N/A`로 표시한다(0으로 나누기 방지). 계산은 서버에서 수행하며 Scout에게는 결과가 제공되지 않는다.

### 5.5 대시보드 (Q8 = A, C, D)

**FR-014 — 파이프라인 현황 위젯**
단계별 작품 수, 단계별 총 오퍼 금액 합계, 병목 구간(평균 체류 일수가 가장 긴 단계)을 표시한다.
- *수용 기준*: 단계별 총 오퍼 금액은 Scout에게 마스킹되지 않는다(오퍼 금액은 Scout 조회 가능). 위젯 항목 클릭 시 해당 단계로 필터링된 작품 목록으로 이동한다.

**FR-015 — 포트폴리오 구성 위젯**
장르별·제작국가별·등급별 작품 분포를 차트로 표시하고, 라인업 갭(작품 수 0건인 주요 장르)을 함께 나열한다.
- *수용 기준*: 집계 대상은 `계약체결` 단계 작품이며, 필터로 전체 파이프라인 기준으로 전환할 수 있다.

**FR-016 — 마감 임박 위젯**
다음 항목을 마감일 오름차순으로 표시한다: 오퍼 유효기간 만료 예정, 판권 계약 만료 예정.
- *수용 기준*: 기본 표시 범위는 향후 30일이며 7/30/90일로 전환 가능하다. 이미 만료된 항목은 별도 강조 표시한다.

### 5.6 데이터 입출력 및 리포트

**FR-017 — CSV/Excel 가져오기 (Q10 = A)**
작품 목록을 CSV 또는 Excel 파일로 일괄 등록할 수 있다.
- *수용 기준*: 업로드 시 검증 결과 미리보기(성공 N건 / 오류 M건, 행 번호와 오류 사유)를 먼저 표시하고 사용자 확인 후 반영한다. 오류 행이 있어도 정상 행만 선택적으로 반영할 수 있다. 템플릿 파일을 다운로드할 수 있다.

**FR-018 — CSV/Excel 내보내기**
현재 적용된 필터 조건 기준의 작품 목록을 CSV 또는 Excel로 내보낸다.
- *수용 기준*: 내보내기 결과에는 요청자의 역할에 따른 마스킹이 동일하게 적용된다(Scout의 내보내기 파일에 MG·재무 데이터가 포함되지 않는다).

**FR-019 — 앱 내 알림 센터 (CQ4 = A)**
헤더의 알림 아이콘에서 미확인 알림 수와 목록을 확인한다.
알림 유형: 멘션(FR-010), 오퍼 유효기간 임박(D-7, D-1), 판권 계약 만료 임박(D-30, D-7).
- *수용 기준*: 마감 알림은 서버 기동 시 및 일 1회 스케줄로 생성되며, 동일 대상에 대해 중복 생성되지 않는다.

**FR-020 — PDF/Excel 리포트 (Q11 = A)**
Analyst·Executive는 다음 리포트를 내보낼 수 있다: 파이프라인 현황 요약, 포트폴리오 구성 요약, 작품 상세 시트.
- *수용 기준*: PDF는 서버에서 생성하며 한글 폰트가 정상 렌더링되어야 한다. 리포트 헤더에 생성 시각과 생성자를 포함한다.

### 5.7 인증 및 권한

**FR-021 — 로그인 (CQ2 = A)**
이메일 + 비밀번호로 로그인한다. 비밀번호는 해시(bcrypt 또는 argon2)로 저장한다.
- *수용 기준*: 로그인 실패 시 이메일 존재 여부를 구분하지 않는 동일한 메시지를 반환한다. 세션은 브라우저 종료 시 만료된다.

**FR-022 — 역할 기반 접근 제어**
3.2절의 권한 매트릭스를 서버 측에서 강제한다.
- *수용 기준*: 권한 없는 API 직접 호출 시 403을 반환하며, 마스킹 대상 필드는 응답 페이로드에서 제외된다. UI 숨김만으로 권한을 구현하지 않는다.

**FR-023 — 사용자 관리**
Executive는 사용자를 생성하고 역할을 지정할 수 있다.
- *수용 기준*: 최소 1명의 Executive가 항상 존재해야 하며, 마지막 Executive의 역할 변경·삭제는 거부된다.

**FR-024 — 시드 데이터**
최초 실행 시 3역할 데모 계정과 예시 작품 데이터가 자동 생성된다.
- *수용 기준*: 시드 데이터만으로 모든 대시보드 위젯이 의미 있는 값을 표시해야 한다(빈 화면이 나오지 않아야 한다).

## 7. 비기능 요구사항 (Non-Functional Requirements)

### NFR-001 — 규모 및 성능 (Q17 = A)
- 데이터 규모: 작품 최대 500건, 사용자 최대 10명, 동시 접속 최대 10명
- 작품 목록 조회(500건, 필터 적용) 응답: p95 500ms 이내
- 대시보드 초기 로드(위젯 3종): 2초 이내
- CSV 가져오기 500행 처리: 10초 이내

### NFR-002 — 실행 및 배포 (Q15 = A)
- 로컬 개발 환경에서 **단일 명령으로 실행** 가능해야 한다 (`docker compose up` 으로 DB 포함 기동)
- 클라우드 배포, 오토스케일링, 무중단 배포는 요구하지 않는다
- 최초 기동 시 스키마 마이그레이션과 시드 데이터가 자동 적용된다

### NFR-003 — 브라우저 및 UI (Q12 = A)
- 대상 브라우저: 최신 버전 Chrome, Edge
- 기준 해상도: 1280px 이상 데스크톱 우선. 768px 이상 태블릿은 레이아웃 붕괴 없이 사용 가능한 수준(best-effort)
- 모바일(768px 미만) 전용 최적화는 하지 않는다

### NFR-004 — 지역화 (Q17 = A)
- UI 언어: 한국어 단일
- 통화: KRW 단일. 다통화 환산 없음
- 날짜 표기: `YYYY-MM-DD`, 시간대는 `Asia/Seoul` 고정

### NFR-005 — 보안 (Q18 = B — SECURITY 확장 비활성)
SECURITY 확장 규칙은 적용하지 않는다. 다만 PoC라도 다음 최소 조치는 기능 요구사항으로 포함한다:
- 비밀번호 해시 저장 (평문 저장 금지)
- 권한 검증은 서버 측에서 수행 (FR-022)
- SQL 인젝션 방지 (ORM 파라미터 바인딩 사용)
- 비밀정보는 환경변수로 주입 (소스코드 하드코딩 금지)

> **⚠️ 명시적 한계**: 위 조치는 PoC 수준이며 프로덕션 보안 요건(감사 로그, 세션 고정 방어, 비밀번호 정책, 레이트 리미팅, 취약점 스캔 등)을 충족하지 않는다. 실제 운영 시 SECURITY 확장 활성화 후 재설계가 필요하다.

### NFR-006 — 복원력 (Q20 = B — Resiliency 확장 비활성)
고가용성, 다중 AZ, 백업·복구(RTO/RPO), 서킷 브레이커 등은 요구하지 않는다. 단일 인스턴스 로컬 실행을 전제한다.

### NFR-007 — 테스트 (Q19 = B — PBT 부분 적용)
- 일반 테스트: 도메인 로직 단위 테스트, 주요 API 통합 테스트
- **속성 기반 테스트(PBT)는 다음 두 영역에만 적용한다**:
  1. **순수 함수** — 재무 계산(FR-013), 단계 체류 일수 계산(FR-006), 마감일 D-day 계산(FR-016)
  2. **직렬화 왕복(round-trip)** — CSV/Excel 내보내기 후 다시 가져오면 원본과 동일한 데이터가 되어야 한다(FR-017 ↔ FR-018)
- 그 외 CRUD·UI 계층에는 PBT를 적용하지 않는다

### NFR-008 — 유지보수성
- 도메인 로직은 UI·프레임워크에 의존하지 않는 별도 계층으로 분리한다
- 재무 계산식은 한 곳에서만 정의되어야 한다(중복 구현 금지)

### NFR-009 — 접근성
- 주요 흐름(작품 등록, 단계 변경, 평가 입력)은 키보드만으로 조작 가능해야 한다
- 텍스트 대비는 WCAG AA(4.5:1) 이상을 목표로 한다
- 스크린 리더 완전 대응은 이번 범위가 아니다

## 11. 성공 기준

1. `docker compose up` 한 번으로 앱과 DB가 기동되고, 시드 데이터로 대시보드 3개 위젯이 모두 의미 있는 값을 표시한다
2. 3개 데모 계정으로 각각 로그인했을 때 권한 매트릭스대로 화면과 API 응답이 달라진다 (특히 Scout 응답에 MG·재무 필드가 존재하지 않는다)
3. 작품을 등록하고 칸반에서 단계를 옮기면 이력이 기록되고 파이프라인 위젯 수치가 즉시 반영된다
4. Analyst가 딜·재무 값을 입력하면 ROI·손익분기가 계산되어 표시된다
5. CSV로 내보낸 파일을 다시 가져오면 데이터가 동일하게 복원된다 (PBT로 검증)
6. 오퍼 유효기간이 7일 이내인 작품이 마감 임박 위젯과 알림 센터에 나타난다
