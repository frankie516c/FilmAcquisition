## 개요

본 시스템은 3개 역할이 **같은 작품 데이터를 서로 다른 시야로** 다룬다. 페르소나 간 가장 중요한 차이는 기능이 아니라 **볼 수 있는 금액의 범위**다. 이 경계는 UI 숨김이 아니라 서버 응답에서 필드를 제거하는 방식으로 강제된다 (FR-022).

| 역할 | 한 줄 정의 | 핵심 권한 경계 |
|---|---|---|
| **Scout** | 작품을 찾아내고 평가하는 사람 | MG·러닝 로열티·계약 조건·재무 분석 **차단** |
| **Analyst** | 돈이 되는지 판단하는 사람 | 딜·판권·재무 전권, 작품 정보는 조회만 |
| **Executive** | 포트폴리오 전체를 보는 사람 | 모든 데이터 조회 가능, 편집은 불가 (사용자 관리만 예외) |

## 페르소나 1 — Scout (Acquisition Manager / Scout)

### 한 줄 정의
영화제·마켓·세일즈 리스트를 훑어 인수 후보를 발굴하고, 직접 보고 평가해 파이프라인에 올리는 실무자.

### 목표
- 검토 중인 작품이 지금 어느 단계에 몇 편 있는지 한눈에 파악한다
- 본 작품의 인상을 잊기 전에 구조화된 형태(스코어카드)로 남긴다
- 내가 밀고 있는 작품이 오퍼 단계에서 멈춰 있지 않은지 확인한다
- 놓친 영화제 이슈나 수상 이력을 작품에 붙여 설득 근거를 만든다

### 불만점 (Pain Points)
- 스프레드시트가 사람마다 달라 같은 작품이 중복 등록되고 어느 게 최신인지 모른다
- 시사 직후 메모를 개인 노트에 적어두면 나중에 누구도 찾지 못한다
- 내가 등록한 작품이 협상 단계에서 어떻게 됐는지 별도로 물어봐야 안다
- 평가가 "좋다/별로다"로만 남아 나중에 왜 그렇게 판단했는지 재구성이 안 된다

### 일상 업무 흐름
1. 세일즈 리스트나 영화제 라인업에서 후보 작품을 발견한다
2. 시스템에 작품을 등록하고 메타데이터·영화제 이력을 채운다
3. 스크리너를 보고 평가 스코어카드를 작성한다
4. 유망한 작품을 `스크리닝` → `평가` 단계로 옮긴다
5. 칸반 보드에서 내 담당 작품의 진행 상황을 확인한다

### 시스템 사용 빈도
**높음 (일 단위)** — 작품 등록과 평가 입력이 주 업무이므로 가장 자주 접속한다

### 권한 경계

| 허용 | 차단 |
|---|---|
| 작품 등록·수정·삭제 (FR-001) | MG·러닝 로열티·계약 조건 조회 (FR-011) |
| 영화제·수상 이력 관리 (FR-002) | 재무 분석 결과(ROI·손익분기) 조회 (FR-013) |
| 평가 스코어카드 작성 (FR-008) | 딜 정보 편집 (Analyst 전용) |
| 코멘트 작성 (FR-009) | 판권 정보 편집 (Analyst 전용) |
| 파이프라인 단계 변경 (FR-005) | PDF·Excel 리포트 생성 (FR-020) |
| 오퍼 금액·유효기간 **조회** (FR-011) | 사용자 계정 관리 (FR-023) |
| CSV 가져오기·내보내기 (FR-017, FR-018) | — |

> **설계 의도**: 오퍼 금액은 파이프라인 운영에 필요하므로 조회를 허용하되, MG·계약 조건·수익성 판단은 차단해 **평가의 독립성**을 유지한다 (requirements.md 가정 A-1).

### 성공의 정의
"오늘 본 작품 3편을 10분 안에 등록하고 평가까지 남겼다. 지난달 내가 올린 작품이 지금 협상 중인 것도 보드에서 바로 확인했다."

### 대표 시나리오
칸(Cannes) 마켓 리스트에서 관심작 5편을 발견한다. CSV 템플릿에 기본 정보를 채워 일괄 등록하고(FR-017), 각 작품에 영화제 초청 이력을 붙인다(FR-002). 스크리너를 본 뒤 2편에 스코어카드를 작성하고(FR-008) 칸반에서 `평가` 단계로 끌어 옮긴다(FR-007). 딜 화면을 열어보지만 MG 항목은 애초에 화면에 존재하지 않는다(FR-022).

## 페르소나 2 — Analyst (재무·비즈니스 분석가)

### 한 줄 정의
Scout가 올린 후보의 딜 조건을 기록하고, 인수비용 대비 수익성을 계산해 인수 여부의 정량적 근거를 만드는 사람.

### 목표
- 오퍼 금액·MG·유효기간을 정확히 기록해 만료로 기회를 잃지 않는다
- 총 인수비용 대비 예상 매출을 계산해 ROI와 손익분기를 산출한다
- 계약된 작품의 영토·기간을 기록해 만료 시점을 미리 파악한다
- 경영진 보고용 리포트를 반복 작업 없이 뽑는다

### 불만점 (Pain Points)
- 오퍼 유효기간이 스프레드시트 구석에 있어 만료 임박을 알아채지 못한다
- 재무 계산식이 사람마다 다른 엑셀 파일에 흩어져 있어 결과를 비교할 수 없다
- 판권 계약 종료일이 다가오는데 알려주는 장치가 없다
- 보고 때마다 데이터를 수동으로 취합해 슬라이드를 다시 만든다

### 일상 업무 흐름
1. Scout가 `평가` 단계로 올린 작품을 확인한다
2. 세일즈사와 협의된 요청가·오퍼 금액·MG·유효기간을 기록한다
3. P&A 예산과 예상 매출을 입력해 ROI·손익분기를 산출한다
4. 계약이 성사되면 판권 영토와 계약 기간을 등록한다
5. 마감 임박 위젯에서 만료 예정 항목을 점검한다
6. 주간 리포트를 PDF로 내보낸다

### 시스템 사용 빈도
**중간 (주 단위, 딜 발생 시 집중)** — 오퍼·협상 단계 작품이 생길 때 집중적으로 사용한다

### 권한 경계

| 허용 | 차단 |
|---|---|
| 딜 정보 전체 등록·수정 (FR-011) | 작품 메타데이터 편집 (조회만 가능) |
| 판권 영토·계약 기간 등록·수정 (FR-012) | 영화제·수상 이력 편집 (조회만 가능) |
| 재무 입력 및 계산 결과 조회 (FR-013) | 평가 스코어카드 작성 (조회만 가능) |
| 파이프라인 단계 변경 (FR-005) | 사용자 계정 관리 (FR-023) |
| 코멘트 작성 (FR-009) | — |
| CSV 가져오기·내보내기 (FR-017, FR-018) | — |
| PDF·Excel 리포트 생성 (FR-020) | — |

### 성공의 정의
"이번 주 만료되는 오퍼가 2건이라는 걸 월요일에 알았다. ROI가 마이너스로 나온 1편은 협상 조건을 다시 잡았다."

### 대표 시나리오
알림 센터에 "오퍼 유효기간 D-7" 알림이 뜬다(FR-019). 해당 작품의 딜 화면에서 오퍼 금액을 상향 조정하고 MG를 기록한 뒤(FR-011), P&A 예산과 예상 매출을 입력한다. 시스템이 총 인수비용·예상 손익·ROI·손익분기를 계산해 보여준다(FR-013). 계약이 성사되자 영토를 `대한민국`으로, 계약 기간을 2년으로 등록한다(FR-012). 주간 보고를 위해 파이프라인 현황 리포트를 PDF로 내보낸다(FR-020).

## 페르소나 3 — Executive (경영진 / C-Level)

### 한 줄 정의
개별 작품의 실무에는 관여하지 않고, 라인업 전체의 구성과 리스크를 확인하며 시스템 사용자를 관리하는 사람.

### 목표
- 확보된 라인업이 장르·국가 면에서 편중되지 않았는지 확인한다
- 파이프라인 어느 단계에서 작품이 정체되고 있는지 파악한다
- 만료가 임박한 계약·오퍼가 있는지 확인한다
- 보고용 자료를 직접 뽑는다

### 불만점 (Pain Points)
- 라인업 현황을 물으면 담당자가 자료를 만드는 데 하루가 걸린다
- 지금 검토 중인 작품이 총 몇 편인지, 총 오퍼 금액이 얼마인지 즉답을 못 받는다
- 장르가 한쪽으로 쏠린 걸 뒤늦게 알게 된다

### 일상 업무 흐름
1. 대시보드에 접속해 파이프라인 현황과 포트폴리오 구성을 확인한다
2. 라인업 갭(작품이 없는 주요 장르)을 점검한다
3. 마감 임박 항목을 확인해 담당자에게 코멘트로 확인을 요청한다
4. 필요 시 리포트를 내보낸다
5. 신규 구성원이 합류하면 계정을 만들고 역할을 부여한다

### 시스템 사용 빈도
**낮음 (주 1~2회, 열람 중심)** — 짧게 들어와 대시보드만 보고 나가는 패턴

### 권한 경계

| 허용 | 차단 |
|---|---|
| 모든 데이터 조회 (금액·재무 포함, 마스킹 없음) | 작품·평가·딜·판권 편집 (전 항목 조회 전용) |
| 코멘트 작성 (FR-009) | 파이프라인 단계 변경 (FR-005) |
| PDF·Excel 리포트 생성 (FR-020) | CSV 가져오기·내보내기 (FR-017, FR-018) |
| 사용자 계정 생성·역할 지정 (FR-023) | — |

> **설계 의도**: Executive는 **읽기 전용 관찰자 + 계정 관리자**다. 데이터 편집 권한이 없으므로 실무 데이터의 우발적 변경 위험이 없고, 대신 유일하게 사용자 관리 권한을 가진다. 마지막 Executive의 역할 변경·삭제는 시스템이 거부한다 (FR-023).

### 성공의 정의
"대시보드를 30초 보고 이번 분기 라인업에 스릴러가 한 편도 없다는 걸 알았다. 만료 임박 계약 1건은 그 자리에서 담당자에게 코멘트로 물었다."

### 대표 시나리오
로그인하면 파이프라인 현황 위젯에서 단계별 작품 수와 총 오퍼 금액, 병목 구간을 확인한다(FR-014). 포트폴리오 구성 위젯에서 장르 분포와 라인업 갭을 본다(FR-015). 마감 임박 위젯에 판권 만료 D-14 작품이 보이자 해당 작품 상세로 이동해 `@analyst 갱신 협의 진행 상황 알려주세요`라고 코멘트를 남긴다(FR-010). 칸반 보드에서는 카드를 끌어도 움직이지 않는다(FR-005).

## 페르소나 대비표

| 항목 | Scout | Analyst | Executive |
|---|---|---|---|
| 주된 관심 | 작품 자체의 가치 | 숫자와 계약 조건 | 전체 구성과 리스크 |
| 접속 빈도 | 일 단위 | 주 단위 (딜 발생 시 집중) | 주 1~2회 |
| 주 사용 화면 | 작품 상세, 칸반 보드 | 딜·재무 화면, 마감 임박 | 대시보드 |
| 데이터 편집 | 작품·평가 | 딜·판권·재무 | 없음 (코멘트 제외) |
| 금액 가시성 | 오퍼 금액만 | 전체 | 전체 |
| 시스템 밖 산출물 | 없음 | PDF·Excel 리포트 | PDF·Excel 리포트 |

## 제외된 페르소나

요구사항 단계에서 다음 역할은 범위에서 제외되었다 (requirements.md 3.1절, Q3 응답 기준):

| 제외 역할 | 제외에 따른 영향 |
|---|---|
| **Acquisition Executive** (최종 승인권자) | 파이프라인 단계 전환에 승인 게이트가 없다. Scout·Analyst가 자유롭게 단계를 옮기고 이력만 남는다 (FR-005) |
| **법무·계약 담당자** | 판권 관리가 영토·기간 기록 수준에 머물며, 권리 충돌 검증과 계약서 관리는 범위 밖이다 (FR-012) |

향후 이 역할들이 추가되면 승인 워크플로(현재 Out of Scope)와 판권 충돌 검증 기능이 함께 필요해진다.
