## 1. 컴포넌트 계층

```
app/(app)/board/
├── page.tsx     서버 · 데이터 조립 + 권한 판정
└── board.tsx    클라이언트 · 드래그 앤 드롭

app/(app)/titles/[id]/page.tsx 안의 "단계 이력" 카드 (서버 렌더)
```

**서버/클라이언트 분리 지점**: 데이터 조회와 권한 판정은 `page.tsx`, 드래그 상호작용은
`board.tsx`. 클라이언트는 `editable` 불리언만 받고 권한 규칙 자체는 모릅니다.

## 2. `board/page.tsx` — 서버 컴포넌트

**동작**
```
requireContext()
listTitles()                                    // 전 작품 + 평가 + 딜
editable = canPerform(role, "pipeline:changeStage")
columns  = 7단계로 분류 + 금액 합계 + 카드 요약
```

**`Board`에 넘기는 props**

| props | 타입 | 비고 |
|---|---|---|
| `columns` | `BoardColumn[]` | 금액은 **이미 문자열** (`bigint`는 직렬화 불가) |
| `editable` | `boolean` | 드래그 활성 여부 |

**권한 없을 때의 안내**: 보드 위에 회색 상자로 표시합니다.
*"현재 역할(경영진)은 pipeline:changeStage 권한이 없습니다. 카드 드래그가 비활성화되며,
API를 직접 호출해도 403이 반환됩니다."*

> 보드 자체는 그대로 보여줍니다. 조회는 전 역할에게 허용되며, 막힌 것은 변경뿐입니다.

## 3. `board.tsx` — 클라이언트 컴포넌트

**상태**

| 이름 | 타입 | 용도 |
|---|---|---|
| `dragId` | `string \| null` | 끌고 있는 카드 |
| `over` | `string \| null` | 드롭 대상 열 (하이라이트) |
| `message` | `string \| null` | 결과 안내 |

**HTML5 드래그 API를 씁니다.** 외부 드래그 라이브러리를 넣지 않았습니다 — 카드를 열 사이로
옮기는 단일 동작에는 기본 API로 충분하고, 의존성이 줄어듭니다.

**이벤트 흐름**
```
onDragStart(card)  → setDragId(card.id)
onDragOver(col)    → e.preventDefault() + setOver(col.stage)     ※ preventDefault 없으면 드롭 불가
onDragLeave        → setOver(null)
onDrop(col)        → fetch → 성공 시 message + router.refresh()
```

**카드 안의 제목은 `<Link>`입니다.** 드래그와 클릭이 한 요소에서 공존하며, 브라우저가
드래그 시작 시 클릭을 억제하므로 충돌하지 않습니다.

**실패 시 상태코드를 그대로 보여줍니다** — `403 FORBIDDEN — 이 작업을 수행할 권한이 없습니다.`
개발 중 디버깅에 유리하고, PoC 성격상 사용자가 곧 개발자입니다.

## 4. 열 구성

```
┌─────────────────────┐
│ 발굴            5   │  ← 단계명 + 건수
│ 900,000,000원       │  ← 오퍼 금액 합계 (없으면 "오퍼 없음")
├─────────────────────┤
│ ┌─────────────────┐ │
│ │ 조용한 이주     │ │  ← 제목 (링크)
│ │ 김스카우트  4.2 │ │  ← 담당자 · 종합점수 (없으면 "미평가")
│ └─────────────────┘ │
└─────────────────────┘
```

**7열 고정 그리드**이며 좁은 화면에서는 가로 스크롤됩니다. 열을 접거나 숨기는 기능은 없습니다 —
파이프라인 전체를 한눈에 보는 것이 이 화면의 목적입니다.

**빈 열도 유지됩니다** (BR-U3-008). 사라지면 드롭 대상이 없어집니다.

## 5. 단계 이력 표시 (작품 상세 안)

**위치**: `titles/[id]/page.tsx` 왼쪽 열, 딜·재무 아래
**타입**: 서버 렌더 (상호작용 없음)

```
단계 이력                                    [append-only]
─────────────────────────────────────────────────────────
발굴        2026-04-21 → 2026-05-23              32일
스크리닝    2026-05-23 → 2026-06-23              31일
평가        2026-06-23 → 2026-07-25              32일
오퍼        2026-07-25 → 진행 중                  1일
─────────────────────────────────────────────────────────
체류 일수 총합 / 등록 후 경과      96일 / 96일  [일치]

두 값이 항상 일치하는 것이 속성 기반 테스트로 검증되는 성질입니다.
```

**`일치`/`불일치` 배지가 이 카드의 핵심입니다.** 불변식을 화면에 드러내 테스트가 놓친 경로를
사용자가 발견할 수 있게 합니다. `불일치`는 빨간 배지로 표시됩니다.

**수정·삭제 버튼이 없습니다.** 헤더의 `append-only` 라벨이 그 이유를 대신합니다.

## 7. 접근성 — 키보드 조작 경로 (2026-07-26 보완)

**초기 구현에는 드래그 앤 드롭만 있어 NFR-009를 충족하지 못했습니다.**
*"작품 등록·단계 변경·평가 입력은 키보드만으로 조작 가능"* 이라는 요구사항 위반이었습니다.

### 7.1 해결 방식 — 카드 안 네이티브 `<select>`

```tsx
<label className="stage-move">
  <span className="sr-only">{card.titleKo} 단계 변경</span>
  <select value={col.stage} onChange={(e) => moveTo(card.id, e.target.value, …)}>
    {STAGES.map(s => <option value={s}>{getStageLabel(s)}{s===col.stage ? " (현재)" : ""}</option>)}
  </select>
</label>
```

**커스텀 드롭다운이 아니라 네이티브 `<select>`를 쓴 이유**: 키보드 조작·스크린 리더·터치가
전부 기본 지원됩니다. 직접 만들면 `role`·`aria-expanded`·포커스 트랩·방향키 처리를 모두
구현해야 하고, 그중 하나만 틀려도 접근성이 깨집니다.

**`sr-only` 라벨**: 화면에는 안 보이지만 스크린 리더는 *"조용한 이주 단계 변경"* 으로 읽습니다.
셀렉트만 있으면 어느 작품의 것인지 알 수 없습니다.

**현재 단계에 `(현재)` 표시**: 셀렉트의 선택값이 현재 단계이므로 시각적으로는 자명하지만,
스크린 리더 사용자에게는 옵션을 훑을 때 어느 것이 현재인지 알려주는 단서가 됩니다.

### 7.2 두 입력 방식이 같은 경로를 쓴다

드래그와 셀렉트가 모두 `moveTo()` 하나를 호출합니다. 경로가 나뉘면 한쪽만 이력을 남기거나
권한 검사를 빠뜨리는 일이 생깁니다.

### 7.3 결과 안내도 접근 가능하게

```tsx
<div className="locked" role="status" aria-live="polite">{message}</div>
```

`aria-live`가 없으면 스크린 리더 사용자는 전환이 성공했는지 알 수 없습니다.
