## 1. 단계 전환

### BR-U3-001 — 전환 권한
**출처**: 권한 매트릭스 5번, US-006, US-007

`pipeline:changeStage`는 **SCOUT과 ANALYST**입니다. **EXECUTIVE는 제외**됩니다.

**근거**: Executive는 열람 전용 관찰자입니다. 실무 데이터의 우발적 변경을 막습니다.

**검증됨**: Executive 403 / Scout 200 / Analyst 200

**화면**: Executive에게는 카드 드래그가 비활성화되고, 그 이유를 안내합니다 —
*"현재 역할은 pipeline:changeStage 권한이 없습니다. API를 직접 호출해도 403이 반환됩니다."*

### BR-U3-002 — 전환 제약은 하나뿐
**출처**: US-006

`from === to`만 거부합니다. 그 외 모든 전환이 허용됩니다.

| 전환 | 허용 |
|---|---|
| 발굴 → 계약체결 (건너뛰기) | ✅ |
| 계약체결 → 평가 (되돌리기) | ✅ |
| 반려 → 오퍼 (되돌리기) | ✅ |
| 오퍼 → 오퍼 (같은 단계) | ❌ 400 `SAME_STAGE` |

**건너뛰기·되돌리기를 허용하는 근거**: 승인 워크플로가 범위 밖(Q9=B)이므로 전이 제약을 두는
것이 오히려 요구사항과 어긋납니다. 되돌리기는 US-006의 수용 기준이 명시적으로 요구합니다
(*"오기입 정정 목적"*).

**같은 단계를 막는 근거**: 아무 변화 없는 이력 레코드가 쌓이면 체류 일수 계산에 0일짜리
구간이 무의미하게 늘어납니다.

### BR-U3-003 — 전환과 이력은 하나의 트랜잭션 (T1)
**출처**: FR-005, FR-006

```
runInTransaction:
  1. StageTransition 생성 (from, to, changedBy, occurredAt=ctx.now, note)
  2. Title.stage 갱신
```

**묶는 이유**: 단계만 바뀌고 이력이 누락되면 "체류 일수 총합 = 등록 후 경과 일수" 속성이
깨집니다. 이 속성은 US-008의 수용 기준이자 화면에 `일치` 배지로 노출됩니다.

**검증됨**: 드래그 후 이력 1건 추가 확인, 총합과 경과 일치 확인

### BR-U3-004 — 사유 메모는 선택
**출처**: US-006

`note`를 비워도 전환이 완료됩니다. 강제하면 사용자가 의미 없는 문자를 채워 넣습니다.

## 2. 이력 조회

### BR-U3-005 — 이력은 수정·삭제할 수 없다
**출처**: FR-006

수정·삭제 API가 존재하지 않으며, 리포지토리에 메서드 자체가 없어 **컴파일 단계에서 차단**됩니다.

### BR-U3-006 — 체류 일수 계산 규칙
**출처**: US-008

Asia/Seoul 달력일 인덱스의 차분으로 계산합니다.

```
구간 경계 = [작품 생성 시각, 전환1, 전환2, …, 현재 시각]
구간 i의 일수 = dayIndex(경계[i+1]) − dayIndex(경계[i])
```

**"시각 차이 ÷ 24시간 후 내림" 방식을 쓰지 않는 이유**: 구간마다 버려지는 나머지가 쌓여
총합이 경과 일수와 어긋납니다. 달력일 인덱스 차분은 경계를 공유하므로 **망원 급수로 정확히
상쇄**됩니다.

**같은 날 여러 번 이동하면** 그 구간들의 일수가 0입니다. 정상이며 `days ≥ 0` 속성을 위반하지
않습니다.

### BR-U3-007 — 현재 단계의 체류 일수
마지막 구간의 `exitedAt`은 `null`이고, 일수는 **요청 시각까지** 계산됩니다. 매일 늘어납니다.

## 3. 칸반 보드

### BR-U3-008 — 빈 단계도 열을 유지한다
**출처**: US-005

작품이 0건인 단계도 열이 사라지지 않습니다. 열이 사라지면 드롭할 대상이 없어져
그 단계로 옮길 수 없게 됩니다.

### BR-U3-009 — 카드 표시 항목
**출처**: US-005

제목 · 담당자 · 종합 점수(없으면 `미평가`)

**단계별 오퍼 금액 합계**를 열 머리말에 표시합니다. 딜이 없는 단계는 `오퍼 없음`입니다.

> 이 금액은 Scout에게도 보입니다. `Deal.offerAmount`는 Scout에게 열려 있는 필드입니다
> (파이프라인 운영에 필요하므로).

### BR-U3-010 — 병목 단계 판정
**출처**: US-018 (대시보드지만 계산은 U3의 D2가 담당)

```
1. 전 작품의 구간을 단계별로 모은다
2. 단계별 평균 체류 일수를 구한다 (구간 수로 나눔, 작품 수가 아님)
3. 종료 단계(계약체결·반려)는 후보에서 제외
4. 평균이 가장 큰 단계를 반환. 동점이면 STAGE_ORDER에서 앞선 단계
```

**종료 단계를 제외하는 이유**: 계속 머무는 것이 정상이라 항상 평균이 가장 커집니다.
포함하면 병목 지표가 무의미해집니다.

**동점 처리를 정한 이유**: 결과가 호출마다 달라지면 안 됩니다.
