## 1. 컴포넌트 구조

```
app/(app)/titles/[id]/page.tsx          서버 컴포넌트 (기존)
└── evidence-section.tsx                "use client" · 근거 탭 전체
    ├── signal-form.tsx                 "use client" · 관측 입력 (동적 폼)
    ├── signal-list.tsx                 "use client" · 목록 + 종류 필터 + 철회
    └── comparable-section.tsx          "use client" · 유사작 + KOBIS 링크
```

**데이터는 서버 컴포넌트가 조회합니다.** `page.tsx`가 `findByTitle(ctx, ...)`를 호출해
props로 내려줍니다. 클라이언트가 조회하면 **행 단위 권한이 걸린 질의를 우회할 길**을
만들게 됩니다.

## 2. 근거 탭의 위치

작품 상세에 **탭을 새로 만들지 않고 섹션으로 붙입니다.**

현재 작품 상세는 카드 섹션이 세로로 이어지는 구조입니다(기본정보 → 딜 → 재무 → 판권 →
단계 이력 → 평가 → 코멘트). 여기에 탭 하나만 도입하면 **같은 화면에 두 가지 탐색 방식**이
생겨 어디에 뭐가 있는지 예측할 수 없게 됩니다.

**배치**: 평가 섹션 **뒤**, 코멘트 섹션 **앞**.

| 위치 | 이유 |
|---|---|
| 평가 뒤 | 평가는 우리 판단, 근거는 그 판단의 재료 — 순서가 자연스럽다 |
| 코멘트 앞 | 코멘트는 대화라 맨 뒤가 맞다. 근거와 코멘트가 붙어 있으면 경계가 흐려진다 |

> Heat 카드는 이 단위에 없습니다 (Q-U6-5 = C). 요약할 데이터가 쌓인 뒤에 만듭니다.

## 4. `signal-form.tsx` — 종류에 따라 바뀌는 폼

**상태**

| 이름 | 타입 | 용도 |
|---|---|---|
| `kind` | `SignalKind` | 선택된 종류 |
| `grade` | `SourceGrade \| ""` | **초기값 빈 문자열** |
| `fields` | `Record<string, string>` | 입력값 |
| `issues` | `Issue[]` | 서버가 준 필드별 오류 |
| `pending` | `boolean` | |

**`grade` 초기값이 빈 문자열인 것이 중요합니다.** `PUBLIC`을 기본 선택으로 두면 사용자가
등급을 **의식하지 않고 넘어갑니다.** 가장 위험한 실수(내부 메모가 공개로 저장됨)가 가장
조용히 일어납니다. 반드시 고르게 합니다 — 도메인 규칙에 기본값을 두지 않은 것과 같은 이유입니다.

**종류에 따른 필드 표시**

| `kind` | 추가로 보이는 입력 |
|---|---|
| `SALES_POINT` | — |
| `REVIEW` | 매체명 · 톤(3지선다) · 키워드 |
| `TRAILER_METRIC` | 수치 |
| `BUYER_INTEREST` | 기관명 |
| `MARKET_NOTE` | 리포트·출처명 |
| `OTHER` | — |

**필드를 숨기지 않고 없앱니다.** `display: none`으로 숨기면 값이 남아 있다가 종류를 바꾼
뒤 함께 전송됩니다. 종류 변경 시 해당 필드를 상태에서 제거합니다.

**등급별 안내와 경고**

```
PUBLIC       출처 URL 필수     "재확인할 수 있는 링크를 넣어주세요"
SEMI_PUBLIC  경고 표시         "개인 실명 대신 조직명까지만 적어주세요.
                               이 규칙은 자동 검증되지 않습니다."
INTERNAL     경고 표시         "내보내기(CSV·PDF·Excel)에 절대 포함되지 않습니다.
                               다만 화면에서는 분석가·경영진이 볼 수 있습니다."
```

**`SEMI_PUBLIC` 문구에 "자동 검증되지 않습니다"를 넣는 이유**: BR-U6-008이 강제가 아니라
운영 규칙이기 때문입니다. 검증되는 것처럼 보이게 두면 사용자가 통과를 안전으로 착각합니다.

**`INTERNAL` 문구가 두 문장인 이유**: "내보내기에서 빠진다"만 쓰면 아무도 못 보는 줄
압니다. **조회 권한과 반출 권한이 다르다**는 걸 정확히 알려야 합니다.

**관측일**

```
관측 시점 *  [2026-07-27]  ← 기본값 오늘, 미래 선택 불가(max=today)
             지금 본 것이 아니라 그 일이 있었던 날짜입니다.
```

브라우저 `max` 속성은 **편의일 뿐**이고 실제 차단은 서버가 합니다 — 화면 검증을 우회해도
`FUTURE_OBSERVATION`으로 막힙니다.

**키워드 입력** (Q-FD-2 = A)

쉼표로 구분해 태그로 만듭니다. 자유 입력이라 `느와르`/`누아르`처럼 표기가 갈릴 수 있고,
이는 감수한 대가입니다. **입력란 아래에 이 작품에 이미 쓰인 키워드를 나열**해 최소한
같은 작품 안에서는 표기가 맞도록 돕습니다 — 자동완성은 아니지만 비용이 거의 없습니다.

**오류 표시**

기존 규약을 그대로 씁니다 — 서버 400의 `fields[]`를 `issues`에 담고 해당 입력 아래에
문구를 표시합니다. **클라이언트에서 검증 규칙을 복제하지 않습니다.** 규칙이 두 곳에 있으면
반드시 어긋납니다.

## 5. `signal-list.tsx`

**종류 필터** (Q-FD-4 = A)

```
[전체 9] [세일즈 3] [리뷰 4] [트레일러 1] [바이어 1]
```

**관측이 0건인 종류는 버튼을 만들지 않습니다.** 누르면 빈 목록이 나오는 버튼은 사용자
시간을 낭비시킵니다.

필터는 **클라이언트에서 처리**합니다. 이미 전부 받아왔고 작품 하나의 관측이 수십 건을
넘지 않으므로 서버 왕복이 낭비입니다.

**한 행의 구조**

```
┌────────────────────────────────────────────────────┐
│ [리뷰] [공개]                          2026-07-14  │
│ Screen Daily                                       │
│ "절제된 연출이 후반부에서 힘을 발휘한다"              │
│ 긍정 · 절제된연출, 후반부                            │
│ 출처 보기 ↗                          이분석 · 철회  │
└────────────────────────────────────────────────────┘
```

**출처 등급 배지의 색**

| 등급 | 토큰 | 이유 |
|---|---|---|
| `PUBLIC` | 중성 (`--line-strong` 테두리) | 위험이 없으므로 눈에 띌 이유가 없다 |
| `SEMI_PUBLIC` | `--warn` | 취급 주의 |
| `INTERNAL` | `--crit` | 가장 강하게. 이 화면에 NDA 자료가 있다는 사실이 보여야 한다 |

**색만으로 구분하지 않습니다.** 배지에 `공개`·`준공개`·`내부` 글자를 함께 넣습니다 —
색각 이상이 있으면 색 구분이 안 되고, WCAG 1.4.1(색에 의존하지 않기)에도 걸립니다.

**철회된 행**

```
┌────────────────────────────────────────────────────┐
│ [리뷰] [공개]  ⊘ 철회됨                2026-07-10  │
│ (본문 흐리게, 취소선 없음)                           │
│ 철회 사유: 다른 작품 리뷰를 잘못 붙였습니다            │
│                              최경영 · 2026-07-12    │
└────────────────────────────────────────────────────┘
```

**취소선을 쓰지 않습니다.** 긴 한글 문장에 취소선을 그으면 읽을 수 없게 되는데, 철회 사유를
이해하려면 원문을 읽을 수 있어야 합니다. 흐리게 + 명시적 `⊘ 철회됨` 배지로 충분합니다.

**접어서 숨기지 않습니다** (BR-U6-002).

**철회 상호작용**

```
[철회] 버튼 → 사유 입력 패널 → [철회 기록] [취소]
```

단계 이동과 **같은 형태**입니다. 이력이 append-only라 사유를 나중에 붙일 수 없으므로
기록 전에 받습니다. 두 곳의 상호작용이 같으면 배울 것이 하나 줄어듭니다.

버튼 표시 조건: `isRetractable(signal, ctx)` — 이미 철회됐거나 Scout가 남의 것이면
**버튼 자체를 그리지 않습니다.** 눌렀다 거부당하는 것보다 없는 편이 낫습니다.

> 화면에 *"버튼이 없는 것은 편의일 뿐이며 실제 차단은 서버에서 이뤄집니다"*를 명시하지
> 않습니다 — 사용자 관리 화면과 달리 여기서는 "왜 못 하는지"가 자명합니다(내 것이 아님).

## 6. `comparable-section.tsx`

**한 행**

```
┌────────────────────────────────────────────────────┐
│ 어느 가족 (2018)              기준: 감독            │
│ 국내 168,000명                                      │
│ 해외: 칸 황금종려상 이후 40개국 판매                  │
│                          KOBIS에서 확인 ↗           │
└────────────────────────────────────────────────────┘
```

**`기준: 감독`을 항상 표시합니다.** 유사작을 볼 때 가장 먼저 물어야 할 것이 "왜 이게
유사작인가"입니다. 기준을 숨기면 확증편향을 막으려고 필수로 만든 필드가 무의미해집니다.

**KOBIS 링크**

`comparableName`과 `releaseYear`로 **화면에서 조립**합니다. 저장하지 않습니다 —
URL 형식이 바뀌면 저장된 링크는 전부 죽지만, 조립하면 함수 한 곳만 고치면 됩니다.

`target="_blank" rel="noopener noreferrer"`를 붙입니다.

**입력 폼**

```
유사작명 *        [                    ]
개봉연도 *        [2018]
유사 판단 기준 *  ( ) 감독 ( ) 장르 ( ) 제작국 ( ) 규모 ( ) 기타
기준 부연         [                    ]
국내 관객수       [        ] 명
해외 성과         [                    ]
출처 등급 *       ( ) 공개 ( ) 준공개 ( ) 내부
```

**`유사 판단 기준`에 기본 선택을 두지 않습니다.** 기본값이 있으면 아무거나 붙은 채로
저장되고, 그러면 이 필드를 필수로 만든 의도가 사라집니다.

**해외 성과가 자유 텍스트인 이유**를 폼에 적습니다:

> 해외 매출은 환율·집계 기간·집계처가 제각각이라 숫자로 두면 비교할 수 없는 것을
> 비교하게 됩니다. 서술로 적어주세요.

## 7. 접근성 (NFR-009)

| 항목 | 처리 |
|---|---|
| 종류 필터 | `<button>` + `aria-pressed`. div가 아니라 버튼이라 탭으로 도달한다 |
| 등급 선택 | `<fieldset>` + `<legend>` 라디오. 그룹임이 스크린 리더에 전달된다 |
| 등급 배지 | 색 + **글자**. 색에만 의존하지 않는다 (WCAG 1.4.1) |
| 철회 확인 패널 | `autoFocus`, `Esc` 취소 — 단계 이동 패널과 동일 |
| 결과 안내 | `role="status" aria-live="polite"` |
| 관측일 | `<input type="date" max={today}>` |
| 대비 | 신규 색 없음. 기존 토큰만 사용 → `contrast.test.ts`가 이미 검사 중 |

**신규 색 토큰을 만들지 않습니다.** 만들면 `contrast.test.ts`의 검사 쌍 목록에 추가해야
하는데, 추가를 잊으면 검사되지 않는 색이 생깁니다.

## 9. 화면에서 직접 확인할 항목

결함 10·11이 연달아 **사람이 화면을 봐야만** 드러났습니다. 통합 테스트는 API 계약만
검사하고 UI 배선은 검사하지 않습니다. E2E 도입 전까지 이 목록을 손으로 확인합니다.

- [ ] 종류를 바꾸면 필드가 실제로 바뀌고, 이전 종류의 값이 함께 전송되지 않는다
- [ ] 등급을 고르지 않으면 저장이 막힌다 (기본 선택이 없다)
- [ ] `PUBLIC` 선택 시 URL 필수 안내가 뜬다
- [ ] `SEMI_PUBLIC`·`INTERNAL` 경고 문구가 실제로 보인다
- [ ] 관측일에 내일 날짜를 넣으면 거부된다
- [ ] **Scout로 로그인해 남의 `INTERNAL` 관측이 목록에 없다**
- [ ] **Scout 본인이 기록한 `INTERNAL` 관측은 보인다**
- [ ] 철회하면 목록에 남고 흐려지며, 상단 `유효 N건`이 줄어든다
- [ ] 철회 버튼이 남의 관측에는 아예 없다
- [ ] **CSV를 내려받아 열었을 때 `INTERNAL` 관측이 없다** (Executive 계정으로도)
- [ ] 유사작의 `기준:`이 목록에 표시된다
- [ ] KOBIS 링크가 새 탭에서 열리고 검색 결과가 나온다
- [ ] 키보드만으로 관측 기록 → 철회까지 완주된다
- [ ] 다크 모드에서 등급 배지 3종이 구분된다
