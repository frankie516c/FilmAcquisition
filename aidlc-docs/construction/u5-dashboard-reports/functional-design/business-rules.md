**작성일**: 2026-07-26
**단계**: 🟢 CONSTRUCTION — U5 Functional Design

규칙 ID는 `BR-U5-nnn`.

## 1. 대시보드 위젯

### BR-U5-001 — 조회 권한
위젯 3종은 **전 역할**이 봅니다. 마스킹은 필드 정책이 처리합니다.

**단계별 오퍼 금액 합계는 Scout에게도 보입니다** — `Deal.offerAmount`가 Scout에게 열린
필드이기 때문입니다 (BR-U4-003).

### BR-U5-002 — 병목 단계에서 종료 단계 제외
**출처**: US-018

`CLOSED_WON`·`REJECTED`는 병목 후보가 아닙니다. 계속 머무는 것이 정상이라 항상 평균이
가장 커져 지표가 무의미해집니다.

동점이면 `STAGES` 순서에서 앞선 단계를 반환해 결과를 결정론적으로 만듭니다.

### BR-U5-003 — 포트폴리오 기본 집계 기준
**출처**: US-019

기본은 `계약체결` 단계 작품입니다. `전체`로 전환할 수 있습니다.

**근거**: "우리가 확보한 라인업"이 질문이지 "검토 중인 것까지 포함한 분포"가 아닙니다.

### BR-U5-004 — 라인업 갭 판정 대상
주요 장르 **6종**(드라마·스릴러·코미디·액션·로맨스·다큐멘터리) 중 0건인 것만 갭으로 표시합니다.

12종 전부를 대상으로 하면 대부분의 장르가 갭으로 나와 신호가 사라집니다.

### BR-U5-005 — 마감 임박 범위와 정렬
**출처**: US-020

기본 30일, 7·90일로 전환 가능. 마감일 **오름차순**이며 오퍼와 판권을 한 목록에 섞습니다.

이미 만료된 항목은 범위와 무관하게 표시되고 위험색으로 강조됩니다 — 지나간 것이야말로
가장 급한 항목입니다.

### BR-U5-006 — 단계 클릭 시 필터 이동
**출처**: US-018

파이프라인 위젯의 단계 행을 클릭하면 `/titles?stage=...`로 이동합니다.
필터가 URL에 실리므로 공유·새로고침이 유지됩니다 (BR-U2-008).

## 2. CSV 내보내기

### BR-U5-007 — 권한
**출처**: 권한 매트릭스 10번

`export:execute`는 **SCOUT·ANALYST**입니다. **EXECUTIVE는 403**입니다.

**Executive를 막는 이유**: 데이터 반출은 실무 담당자의 작업입니다. Executive에게는 대신
리포트 기능이 있습니다.

**검증됨**: Scout 200 / Analyst 200 / Executive 403

### BR-U5-008 — 컬럼도 마스킹된다
**출처**: FR-018, US-022

역할이 볼 수 없는 필드는 **컬럼 자체가 빠집니다.** 빈 열이 남지 않습니다.

**검증됨**: Scout 9컬럼 / Analyst 17컬럼

### BR-U5-009 — 제외된 컬럼을 사용자에게 알린다
응답 헤더 `X-Omitted-Columns`로 전달하고 화면이 표시합니다 —
*"24행 내보냈습니다. 권한이 없어 제외된 컬럼: 요청가, MG, …"*

**근거**: "왜 내 파일에는 MG 컬럼이 없지?"를 추측하게 두지 않습니다.

### BR-U5-010 — 게이트 → 파일 생성 순서
직렬화 게이트를 통과한 데이터만 CSV 생성 단계로 넘깁니다.

**역순이면** 마스킹 대상 값이 이미 문자열에 포함된 뒤 제거를 시도하게 됩니다.

### BR-U5-011 — 필터 범위 일치
내보내기는 화면에 적용된 필터와 같은 범위를 씁니다. 사용자가 보고 있는 것과 받는 것이
달라지면 안 됩니다.

## 3. CSV 가져오기

### BR-U5-012 — 권한
`import:commit`은 **SCOUT·ANALYST**입니다. Executive는 403입니다.

### BR-U5-013 — 미리보기는 아무것도 저장하지 않는다
**출처**: US-021

`mode` 없이 호출하면 검증만 하고 결과를 반환합니다. DB 변화가 없습니다.

**검증됨**: 미리보기 후 작품 수 변화 없음

### BR-U5-014 — 오류를 행 번호·컬럼·사유로 보고한다
**출처**: US-021

```json
{"totalRows":5,"validCount":2,
 "issues":[{"rowNumber":4,"column":"titleKo","message":"제목을(를) 입력해주세요."},
           {"rowNumber":5,"column":"productionYear","message":"제작연도는 1888년 이후여야 합니다."},
           {"rowNumber":6,"column":"장르","message":"알 수 없는 장르: 없는장르"}]}
```

**행 번호는 1-based이며 헤더가 1행**입니다. 사용자가 스프레드시트에서 그 줄을 바로 찾을 수
있어야 합니다.

### BR-U5-015 — 두 가지 반영 모드
**출처**: US-021

| 모드 | 동작 |
|---|---|
| `VALID_ONLY` | 정상 행만 반영, 오류 행 제외 |
| `ALL` | 오류가 하나라도 있으면 **400으로 거부** |

**`ALL`이 "무시하고 다 넣기"가 아닙니다.** 검증에 실패한 행은 저장할 방법이 없으므로,
`ALL`은 "전부 정상일 때만 전부 넣기"입니다.

**검증됨**: 오류 3건 있는 파일에 `ALL` → 400, 행별 사유 반환

### BR-U5-016 — 반영은 원자적 (T5)
선택된 행 집합 전체가 하나의 트랜잭션입니다. 일부만 반영된 중간 상태를 만들지 않습니다.

### BR-U5-017 — 클라이언트가 보낸 행을 신뢰하지 않는다
반영 시 **원본 파일을 다시 파싱해 서버가 스스로 판정**합니다.
미리보기 결과를 클라이언트가 되돌려 보내는 것을 그대로 쓰면 검증 우회가 됩니다.

### BR-U5-018 — 장르 표기
한국어 라벨(`드라마`)과 코드(`DRAMA`)를 모두 받습니다. 구분자는 `;` `,` `|`을 허용합니다.
알 수 없는 값이 있으면 그 행 전체를 오류로 처리합니다.

### BR-U5-019 — BOM 처리
파서가 선두 BOM을 먼저 제거합니다. 제거하지 않으면 첫 컬럼 헤더가 `﻿제목`이 되어
`MISSING_COLUMN`이 납니다. Excel이 저장한 CSV가 이 형태입니다.

## 4. 알림

### BR-U5-020 — 자기 알림만 본다
`GET /api/notifications`는 `ctx.userId`의 알림만 반환합니다. 남의 알림 ID로 읽음 처리를
시도하면 **404**입니다(403이 아님 — 존재 여부를 알려주지 않습니다).

### BR-U5-021 — 마감 알림 임계값
**출처**: US-024

| 대상 | 임계값 |
|---|---|
| 오퍼 만료 | `[7, 1]` |
| 판권 만료 | `[30, 7]` |

**정확히 일치할 때만** 발동합니다. 범위 조건이 아닙니다.

**근거**: 범위면 D-7부터 D-0까지 매일 알림이 쌓입니다. 정확 일치가 "임계값 하나당 알림 하나"를
보장합니다.

**결과**: D-3이나 D-6인 오퍼에는 알림이 생기지 않습니다. **정상 동작입니다.**

### BR-U5-022 — 수신자는 작품 담당자
담당자가 없는 작품은 알림을 만들지 않습니다(보낼 대상이 없음).

### BR-U5-023 — 중복 방지
UNIQUE 제약 위반(`P2002`)을 잡아 `skipped`로 처리합니다. 사전 조회만으로는 경쟁 상태를
막을 수 없습니다.

**검증됨**: 3회 연속 스캔 → 생성 1 → 0 → 0 (통합 테스트 자동 검증)

### BR-U5-023a — 중복 판정 키는 NOT NULL이어야 한다 (2026-07-26)
**출처**: 설계 결함 수정

`@@unique`에 nullable 컬럼(`titleId`)이 포함되면 PostgreSQL의 `NULL != NULL` 규칙 때문에
**그 행에는 제약이 걸리지 않습니다.**

중복 판정을 `dedupeKey` 단일 NOT NULL 컬럼으로 옮겼습니다. 키 생성은
`src/domain/notification-key.ts`의 순수 함수가 담당하며, 작품이 없으면 `-` 자리표시자를
넣어 **키 자체는 항상 존재**합니다.

`marker`는 화면 표시용으로 남았습니다 — 중복 판정과 표시라는 두 역할을 한 컬럼이 겸하던
것을 분리했습니다.

### BR-U5-024 — 스캔은 수동 트리거
**설계와의 차이**: 요구사항은 기동 시 1회 + 일 1회 스케줄이었으나, 스케줄러가 범위 밖이라
**알림 센터의 버튼**으로 대체했습니다. 중복 방지가 있어 몇 번을 눌러도 안전하며,
그 자체가 중복 방지의 확인 수단이 됩니다.

## 5. 리포트

### BR-U5-025 — 권한
`report:generate`는 **ANALYST·EXECUTIVE**입니다. **Scout는 403**입니다.

**Scout를 막는 이유**: 리포트에 재무 정보가 포함되며, Scout는 그 데이터에 접근할 수 없습니다.

**검증됨**: Scout 403 / Analyst 200 / Executive 200

### BR-U5-026 — 머리말 필수
**출처**: US-025

모든 리포트에 **생성 시각과 생성자**가 들어갑니다. 인쇄본이 돌아다닐 때 언제·누가 뽑은
자료인지 없으면 신뢰할 수 없습니다.

### BR-U5-027 — PDF 생성 방식 (설계와 다름)
**출처**: US-025 — **의도적 대체**

요구사항은 "서버에서 생성"이었으나 **인쇄용 화면 + 브라우저 인쇄**로 대체했습니다.

**근거**: 서버 PDF 생성은 한글 TTF를 저장소에 포함해야 하며(수 MB), 로컬 프로토타입에서
비용 대비 이득이 없다고 판단했습니다.

**수용 기준 충족 여부**

| 기준 | 충족 |
|---|---|
| 한글이 깨지지 않아야 한다 | ✅ 브라우저가 시스템 폰트 사용 |
| 머리말에 생성 시각·생성자 | ✅ |
| **서버에서 생성** | ❌ **클라이언트에서 생성** |

이 차이를 `/reports` 화면·서비스 주석·README·상태 문서에 모두 명시했습니다.

### BR-U5-028 — Excel은 BOM 포함 CSV
`.xlsx` 바이너리가 아니라 BOM이 붙은 UTF-8 CSV입니다. Excel이 인코딩을 올바로 인식해
한글이 정상 표시됩니다.
