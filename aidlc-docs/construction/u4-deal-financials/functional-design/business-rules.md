## 1. 권한

### BR-U4-001 — 딜·판권·재무 변경은 Analyst 전용
**출처**: 권한 매트릭스 6~8번

`deal:update`, `rights:write`, `financial:update` 모두 **ANALYST 단독**입니다.
Scout도 Executive도 403입니다.

**Executive까지 막는 이유**: Executive는 열람 전용 관찰자입니다(페르소나 정의).
전 데이터를 볼 수 있지만 바꾸지는 않습니다.

**검증됨**

| 동작 | SCOUT | ANALYST | EXECUTIVE |
|---|---|---|---|
| 딜 수정 | 403 | 200 | 403 |
| 판권 등록 | 403 | 201 | 403 |
| 재무 수정 | 403 | 200 | 403 |

### BR-U4-002 — 재무 조회는 Analyst·Executive
**출처**: US-017

`getFinancials()`는 진입에서 `requireRole(ANALYST, EXECUTIVE)`로 Scout를 차단합니다.

**필드 정책에서도 이미 차단되는데 서비스에서 또 막는 이유**: 불필요한 DB 조회를 하지 않기
위함입니다. 필드 정책만 있으면 조회한 뒤 버리게 됩니다.

> 두 층위가 **같은 결론**을 내야 합니다. 어긋나면 한쪽이 버그입니다.

## 2. 마스킹

### BR-U4-003 — Scout에게 차단되는 것
**출처**: FR-022, US-014

| 대상 | 방식 |
|---|---|
| `Deal.askingPrice`, `minimumGuarantee`, `runningRoyaltyRate`, `contractTerms` | 필드별 — 키 부재 |
| `FinancialModel` 전체 | 엔티티 단위 — 관계 필드째 부재 |

**`null`이 아니라 키가 없어야 합니다.** `"minimumGuarantee": null`은 실패입니다.

**검증됨**: Scout 응답 페이로드에 해당 키 전부 부재. Analyst·Executive는 전 필드 포함.

### BR-U4-004 — 화면 마스킹 표시
**출처**: US-014

차단된 필드는 숨기지 않고 **`••• 권한 없음`으로 표시**합니다.

**근거**: 필드가 사라지면 "이 작품은 MG가 없다"로 오해합니다. 자리를 남기고 권한 문제임을
알리는 것이 정확합니다.

재무는 카드 전체를 안내 문구로 대체합니다 —
*"현재 역할에게는 FinancialModel 엔티티 전체가 차단되어 있습니다. 필드를 하나씩 지우지 않고
관계째로 제거하므로, 빈 객체가 남아 '재무 데이터가 존재한다'는 사실조차 새어 나가지 않습니다."*

### BR-U4-005 — 내보내기에도 같은 규칙
**출처**: FR-018

CSV 컬럼도 같은 정책으로 제거됩니다. Scout 파일 9컬럼, Analyst 파일 17컬럼.

**순서 규칙**: 직렬화 게이트 → CSV 생성. 역순이면 마스킹 대상 값이 이미 문자열에 들어간
뒤 제거를 시도하게 됩니다.

## 3. 딜

### BR-U4-006 — upsert 방식
딜은 작품당 1건이므로 `upsert`입니다. 없으면 생성, 있으면 갱신입니다.
사용자에게 "딜 생성"과 "딜 수정"이 구분되지 않습니다.

### BR-U4-007 — 부분 갱신
전달되지 않은 필드는 건드리지 않습니다(Prisma가 `undefined`를 무시). `null`을 명시하면 지웁니다.

### BR-U4-008 — 날짜 순서
`offerExpiryDate >= offerSubmittedAt`. **같은 날은 허용**됩니다.

**검증됨**: 제출일 2026-08-01, 유효기간 2026-07-01 → `400 {"path":"offerExpiryDate"}`

### BR-U4-009 — 금액은 비음수 정수
음수·소수·문자는 400입니다. 상한은 8바이트 정수 범위입니다.

**검증됨**: `offerAmount: -500` → `400 "금액은 0 이상이어야 합니다."`

## 4. 판권

### BR-U4-010 — 영토 최소 1개
빈 배열은 400입니다. 영토 없는 판권은 의미가 없습니다.

### BR-U4-011 — 종료일은 시작일보다 이후
**같은 날은 거부**됩니다 (딜과 부등호가 다름 — BR-U4-008 대조).

**검증됨**: 시작일 = 종료일 = 2026-01-01 → `400 "계약 종료일은 시작일보다 이후여야 합니다."`

### BR-U4-012 — 충돌 검증 없음
영토·기간이 겹쳐도 저장합니다. **범위 밖으로 확정된 사항**이며 US-015가 명시적으로 허용합니다.

**검증됨**: 겹치는 판권 2건 등록 → 둘 다 201

## 5. 재무 계산

### BR-U4-013 — 산식은 D1에만 있다
**출처**: NFR-008

```
총 인수비용   = 기준액 + P&A 예산 + 기타 비용
예상 손익     = 예상 매출 − 총 인수비용
손익분기 매출 = 총 인수비용
ROI(%)       = 예상 손익 ÷ 총 인수비용 × 100
```

`FinancialService`는 **호출만 하고 구현하지 않습니다.** 대시보드·내보내기·리포트도 같습니다.

**검증됨**: MG 8억 + P&A 14억 + 기타 2억 = 24억, 매출 38억 → 손익 14억, ROI 58.33%.
화면과 CSV가 일치하며 손 검산과도 맞습니다.

### BR-U4-014 — 기준액 선택
```
기준액 = MG ?? 오퍼 금액 ?? 0
```
MG가 지급 확정 금액이므로 우선합니다.

### BR-U4-015 — 0으로 나누기
총 인수비용이 0이면 ROI는 `null`이고 화면은 `N/A`입니다. **예외를 던지지 않습니다.**

손익분기는 `0`으로 정상 반환합니다 — 0원짜리 인수의 손익분기는 0원이 맞습니다.

### BR-U4-016 — ROI 정밀도
소수 둘째 자리까지 **버림**입니다. 반올림이 아닙니다.

**근거**: `bigint` 나눗셈이 이미 버림이라 규칙이 일관되고, 버림은 항상 보수적이라 수익성을
과대평가하지 않습니다.

**계산 순서**: `(손익 × 10000n) / 총비용` 을 `bigint`로 먼저 구한 뒤 `Number()`로 변환합니다.
`bigint`를 먼저 `number`로 바꾸면 큰 값에서 정밀도가 손실됩니다.
