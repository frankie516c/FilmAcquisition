## 3. 커버리지에 대하여

**커버리지는 측정하지 않습니다.** NFR-007이 커버리지 목표를 정하지 않았고, 이 프로젝트의
테스트 전략은 "코드 라인을 얼마나 밟았는가"가 아니라 **"불변식이 성립하는가"** 이기 때문입니다.

예를 들어 `D2 DwellTimeCalculator`의 `calculateDwellSegments`는 라인 커버리지 100%를 한 번의
호출로 달성할 수 있지만, 그것이 "체류 일수 총합 = 등록 후 경과 일수"를 보장하지는 않습니다.
그 속성은 임의 입력 100회로만 검증됩니다.

커버리지가 필요해지면 `@vitest/coverage-v8`을 추가하고 `vitest run --coverage`를 쓰면 됩니다.

## 4. 속성 기반 테스트 (17개 속성)

**설정**: 속성당 **100회 실행**, 고정 시드(`20260725`), 실패 시 자동 축소(shrinking).
시드를 고정했으므로 실패는 항상 재현됩니다.

### D1 FinancialCalculator — 5개

| # | 속성 |
|---|---|
| P1 | 손익분기 매출 = 총 인수비용 (항상) |
| P2 | 매출 = 총 인수비용이면 손익 0, ROI 0% |
| P3 | 매출 증가 시 손익·ROI 비감소 (단조성) |
| P4 | 총 인수비용 0이면 ROI `null`, 예외 없음 |
| P5 | 모든 결과 금액이 `bigint` 유지 |

입력 범위 `0n ~ 10^15n`(1000조) — 실무 최대치를 크게 넘는 범위까지 검증합니다.

### D2 DwellTimeCalculator — 4개

| # | 속성 |
|---|---|
| P1 | 모든 체류 일수 ≥ 0 |
| P2 | **체류 일수 총합 = 등록 후 경과 일수** |
| P3 | 구간이 연속하고 겹치지 않음 |
| P4 | 이력 0건이면 구간 1개, `exitedAt = null` |

> P2가 이 프로젝트에서 가장 중요한 속성입니다. `dayIndex` 차분이 망원 급수로 상쇄되기 때문에
> 성립하며, "시각 차이 ÷ 24시간 후 내림" 방식이면 나머지가 쌓여 깨집니다.

### D3 DeadlineCalculator — 4개

| # | 속성 |
|---|---|
| P1 | 같은 날이면 시각이 달라도 D-0 |
| P2 | 만료일 하루 증가 시 D-day 정확히 1 증가 |
| P3 | 시·분·초만 바뀌면 결과 동일 (Asia/Seoul 달력일 기준) |
| P4 | D-day < 0 이면 조회 범위와 무관하게 항상 `expired` |

### D4 CsvSerializer — 4개

| # | 속성 |
|---|---|
| P1·P2 | **왕복 무손실** — 한글·쉼표·큰따옴표·줄바꿈·이모지 포함 |
| P3 | 임의의 손상된 입력에도 예외를 던지지 않음 |
| P4 | 첫 행이 항상 `columns`의 header 순서와 일치 (BOM 제거 후) |

> 생성기에 `,` `"` `\r` `\n` 한글 이모지를 **명시적으로** 포함시킵니다. 무작위 유니코드에만
> 의존하면 이 문자들이 거의 생성되지 않아 P2가 실질적으로 검증되지 않습니다.

## 5. 권한 단위 테스트 (11개)

`tests/unit/authz.test.ts` — X1 권한 정책과 X2 직렬화 게이트를 검증합니다.

| 검증 | 내용 |
|---|---|
| 기본값 차단 | 미등재 필드·미등재 엔티티가 전부 `false` |
| Scout 마스킹 경계 | 오퍼 금액은 열려 있고 MG·러닝로열티·계약조건·재무는 차단 |
| 동작 권한 12항목 | 역할별로 정확히 구분 |
| **키 부재** | 차단 필드가 `null`이 아니라 **키 자체가 없음** (`'field' in view === false`) |
| 타입 변환 | `bigint` → 문자열, `Date` → ISO. `JSON.stringify` 예외 없음 |
| 엔티티 단위 차단 | 관계 필드째 제거 — 빈 객체를 남기지 않음 |
| 내보내기 | 차단 필드가 컬럼 목록에서도 제거됨 |
| **원시값 배열 유지** | `genres`·`cast`가 미등록 관계로 오인돼 사라지지 않음 (회귀 방지) |
| 빈 배열 유지 | `[]`도 필드로 유지 |
| 미등록 객체 배열 차단 | 안전 규칙은 여전히 작동 |

> 마지막 세 건은 **실제로 발생했던 결함**에 대한 회귀 방지입니다. 직렬화 게이트가 배열이면
> 무조건 미등록 관계로 보고 차단해서 `genres`·`territories`가 모든 API 응답에서 조용히
> 사라졌습니다. 서버 렌더링 화면은 Prisma 결과를 직접 읽어 증상이 보이지 않았고,
> API를 직접 호출해야만 드러났습니다.

## 6. 테스트가 실패할 때

1. 출력의 반례(counterexample)를 확인합니다. 속성 기반 테스트는 **최소 반례로 축소**해 보여줍니다
2. 시드가 고정되어 있으므로 그대로 다시 실행하면 같은 실패가 재현됩니다
3. 반례를 단위 테스트로 고정한 뒤 코드를 고칩니다
4. 전체를 다시 실행합니다

**속성이 틀렸을 가능성도 검토하세요.** 요구사항이 바뀌었다면 고쳐야 할 것은 코드가 아니라 속성입니다.
